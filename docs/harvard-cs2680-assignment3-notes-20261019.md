## 核心判断

CS2680 作业3与 Eval Lab 重合在固定任务、独立评分、基线比较和实验记录。它最值得借鉴的是把真实智能体的质量、费用和完成速度放进同一套优化反馈中。

Eval Lab 已有失败机制、反证、回归和测量合同基础，不宜把课程方案再做成一套平行评测平台。适合的方向是先核对现有指标和记录是否足以回答“同一个任务有没有更可靠、更省钱、更快”，再决定是否补充一个小范围实验。A2 的独立验收与 B 线的比较实验继续各自遵守已有职责。[仓库方法论](https://github.com/aerenkolstein-code/llm-evaluation-lab/blob/4e1466def9d56d72901f815735924cabcb916703/docs/methodology.md)

## 课程中直接相关的设计

作业3要求学生优化自己的智能体。课程提供任务和独立评分设施，在干净的任务环境中验证结果；学生根据评分反馈决定继续尝试或结束，并记录模型及工具调用。比较同时关注解决任务数、每个成功任务的费用和耗时；符合门槛的结果采用多指标非支配分层。运行有预算和时间限制，未完成任务及失败原因会被保留。[官方作业3说明](https://cs2680.seas.harvard.edu/assignments/assignment3)

这提供了一个可借鉴的结构：被测智能体负责执行和优化，评测设施负责判定及记录。课程的模型价格、算力、并发额度和排行榜门槛属于教学环境，不转成我们项目的运行权限或预算。

## 可采用的评测改进

### 在质量门槛之后比较成本和速度

保留安全、权限、隐私及核心业务不变量的硬门槛。通过门槛的候选，再比较质量、费用及耗时；不能以更低成本抵消硬门槛失败。

可在符合相同适用条件的候选之间，展示哪些结果在各指标上均不差、且至少一项更好。先不引入人为加权总分，也不把课程的排名规则直接覆盖 BM0。BM0 当前不输出排名；新增比较视图仍需单独确定适用范围、方法版本及授权。

### 把分母和完整性写在结果旁边

每份报告同时交代预先计划的尝试、实际记录的尝试、可评分的尝试、成功数和各类终态。缺失观测不能通过只展示成功样本而消失。

模型能力比较沿用 BM0 的适用性与分母规则。若另设端到端服务可靠性指标，应独立定义其总体和分母，让读者同时看见“模型在可评分任务上怎样”和“系统面对全部预定任务时怎样”，不能混成一个失败率。已有合同要求因观测不全而抑制汇总时，继续抑制，不补算局部成绩。

### 明确每个成功任务的费用含义

在实验完整、费用可归属且成功数大于零时，可考虑：

`每个成功任务的费用 = 该实验全部预定尝试的可归属费用 / 成功任务数`

分子应包含失败尝试和重试的费用，不能只加总成功样本。记录实际费用、估算费用及未知费用的来源和范围；缺少账单不填零，观察到账户余额不变也不证明免费。

成功数为零时，该比值不定义，单列总费用与零成功事实。账单未结算、费用不完整或不同候选计价范围不一致时，不据此宣称某候选更便宜。若现有合同已有同义指标，应复用其定义和标识。

### 用端到端时间检验优化

明确计时起止点，并把工具等待、重试及必要评分反馈是否计入写进协议。总体吞吐、单任务延迟和用户等待时间应分开报告，避免并行处理降低平均摊销时间后，被误写为每个用户都更快收到结果。

必要时增加单任务延迟分布；小样本或不完整观测须保留解释限制。更短的日志、更少的轮数可以辅助诊断，不能直接替代实际耗时。

### 让继续尝试和停止策略成为可检验变量

可以在同一批任务上比较单次尝试与有界重试，或比较不同上下文和模型路由策略，但每个重试必须保留新身份及父尝试关系，不能覆盖原失败。

预先声明预算、超时、停止和清理规则，检查达到边界后是否按约定停止。平台定期检查额度不等于严格不会超额；我们的最坏费用估计、预留及停止规则继续独立成立。

### 保留足够证据解释改善和退步

每次实验绑定案例、输入、候选代码、模型解析结果、提示及工具配置、环境、评分器、尝试身份和预算规则。对比时先核对条件，再解释差异。

失败记录至少能区分业务未完成、原有能力回归、工具或供应商错误、评分失败、超时、中断、未执行与不可评估。保留每次尝试的脱敏轨迹、独立判定和费用时间依据。工具返回成功、模型自称完成和评测通过是三种不同证据。

公开材料继续使用脱敏或合成案例；不把凭据、完整私人会话或可反查私人来源的标识放入公开轨迹。

## 未来小实验的候选框架

如后续单独批准，可先选一种有稳定接口、可独立判定的任务，复用现有测量合同，做一组基线与单变量干预比较。

| 项目 | 实验前应固定的内容 |
| --- | --- |
| 被测对象 | 模型、智能体运行框架或完整系统；明确评测类别 |
| 任务 | 版本、适用范围、可见输入及保留评测集 |
| 尝试 | 成对身份、重复次数、重试规则和完整清单 |
| 干预 | 一项可解释的变化，例如上下文整理或有界重试 |
| 判定 | 独立评分器、业务成功条件、匹配对照及回归门 |
| 资源 | 单次与整批上限、计费来源、计时范围和收尾预留 |
| 结果 | 全部终态、协议允许的质量汇总、费用及时间、退步案例 |
| 结论 | 改善在哪些条件下成立，哪些问题仍不可评估 |

调试可见任务与保留评测任务应分开，防止反复优化同一批样本后把记住题目当成能力提升。多变量同时变化时，不作单一原因归因。

这是一份候选实验框架；当前没有分配任务、规定执行日期或启动任何实验。

## 当前保存结论

优先借鉴质量、费用和端到端时间的联合观察，以及依据独立反馈优化执行策略的方法。继续使用 Eval Lab 已有的失败机制、反证、独立验收和证据边界。

下一次规划若讨论采用，先核对现有字段、评分接口及统计协议能否覆盖目标，再列出必要的最小差异。本备忘录不修改仓库当前路线，不构成 Harvard 作业完成或提交记录，也不证明新增能力已经实现。
